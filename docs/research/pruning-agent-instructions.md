## 1. The core position: keep it almost empty

- **Never auto-generate it.** "Never run it. If you find one that was auto-generated, delete it. The file it creates will burn tokens, distract the agent, and go out of date faster than a pear on a hot day." He cites research that "unnecessary context files make tasks harder, not easier" (arXiv 2602.11988). *Never Run Claude /init*, 2026-02-24. https://www.aihero.dev/never-run-claude-init **[V]** Same advice in the video of the same name, same day: "why minimal documentation is better than comprehensive guides". https://www.youtube.com/watch?v=9tmsq-Gvx6g **[V]** (description only)
- **The bar for a line: undiscoverable *and* globally relevant.** "Almost nothing. My entire `CLAUDE.md` is: you are on WSL on Windows. Six words. It's there because WSL has unintuitive path resolution issues that the agent can't discover on its own. That's the bar: only include what is both **undiscoverable** and **globally relevant**." Same article. **[V]**
- **By August 2026 the file is for pointers.** In `retro`: "`CLAUDE.md`/`AGENTS.md`: these files are pushed to the context window of any agent working in this repo. They should be used incredibly sparingly, usually only for **navigation pointers** to other files." https://github.com/mattpocock/skills/blob/main/skills/engineering/retro/SKILL.md **[V]** (line added in the first commit of `retro`, `8fa1886`, 2026-08-24). The docs page says it more bluntly: "`AGENTS.md` and `CLAUDE.md` are for navigation pointers and little else." https://github.com/mattpocock/skills/blob/main/docs/engineering/retro.md **[C]**
- **The codebase matters more than the file.** "Your codebase, way more than your prompt or your AGENTS.md file, is the biggest influence on AI's output." *How To Make Codebases AI Agents Love*, 2026-02-26. https://www.aihero.dev/how-to-make-codebases-ai-agents-love **[V]**

## 2. Why: his reasoning

- **It's always loaded, into every session.** "`CLAUDE.md` is **global**. Every instruction applies to every session: frontend, backend, docs, database, all of it. … Every line you add has a cost that compounds across every session, whether it's relevant or not." (*Never Run Claude /init*, "The Globality Problem") **[V]** The `writing-for-agents` docs page says the same: "Anything that applies in one session out of ten costs context load in the other nine." https://github.com/mattpocock/skills/blob/main/docs/productivity/writing-for-agents.md **[C]**
- **It squeezes the working context.** The system prompt (which includes `CLAUDE.md`) is "hardwired the moment the agent starts", so a bigger one leaves "less room for the phases that actually do the work" (exploration, implementation, testing). (*Never Run Claude /init*) **[V]**
- **Instruction budget.** "Each sentence in your `CLAUDE.md` is an instruction." Same article. **[V]** His numbers for the budget vary (see §8).
- **Dilution.** "A long AGENTS.md both costs tokens and dilutes itself: the more instructions in context, the less reliably the model follows any one of them." AI Coding Dictionary, *AGENTS.md* (first committed 2026-05-01). https://github.com/mattpocock/dictionary-of-ai-coding/blob/main/dictionary/AGENTS.md.md **[V]** "The tell is an agent that ignores rules you know are in its context: they're in there, but buried." *Progressive disclosure* entry. https://github.com/mattpocock/dictionary-of-ai-coding/blob/main/dictionary/Progressive%20disclosure.md **[V]**
- **Staleness actively misleads.** "For AI agents that read documentation on every request, stale information actively poisons the context." *A Complete Guide To AGENTS.md*, 2026-01-18. https://www.aihero.dev/a-complete-guide-to-agents-md **[V]** File and service references are "the worst category. … The moment you rename a file, move a service, or change an implementation, this documentation is wrong. It now **actively misleads** the agent." (*Never Run Claude /init*) **[V]**
- **How files grow: the "ball of mud" loop.** "The agent does something you don't like / You add a rule to prevent it / Repeat hundreds of times over months / File becomes a 'ball of mud'." Also: "Different developers add conflicting opinions. Nobody does a full style pass." (*A Complete Guide To AGENTS.md*) **[V]** Later name for it: **sediment**, "stale layers that settle because adding feels safe and removing feels risky". (`writing-for-agents` SKILL.md) **[V]**

## 3. What to cut

From *Never Run Claude /init* ("What Init Actually Generates"), all **[V]**:

- **Command listings.** "Init loves dumping every script from `package.json` into the file. These are trivially discoverable."
- **Architecture descriptions.** "Framework names, rendering modes, compiler settings. The agent can discover all of this from config files and imports."
- **File and service references.** (above)
- **Implementation patterns.** Discoverable from the code, "and it's only relevant to a fraction of sessions."
- His summary: "everything init generates is either trivially discoverable from source or will go stale. Your file system *is* the documentation."

From `writing-for-agents` (Pruning section), https://github.com/mattpocock/skills/blob/main/skills/productivity/writing-for-agents/SKILL.md **[V]**:

- **Caches of the environment.** "The **environment** is a source of truth too (`package.json` scripts, config files, the directory layout, `--help` output), and a document that restates it is a **cache**: a copy of a lookup, earning its load only when the lookup is expensive. … Leave the one-file, one-command lookups to the environment, where they cannot go stale." (added 2026-07-28, commit `f054def`)
- **No-ops.** "An instruction the model already obeys by default pays load to say nothing. The test (does it change behaviour versus the default?) is model-relative … settle it by running the document, not by debate. When a sentence fails, delete the whole sentence rather than trim words from it."
- **Duplication.** "Keep each meaning in a **single source of truth**." Duplication "costs maintenance and tokens, and inflates a meaning's prominence".
- **Lines that lost relevance**: exposition, a branch that should be disclosed, or anything gone stale.
- **Prohibitions where a positive works.** "Steering by prohibition drags the forbidden behaviour into context and makes it _more_ available. … Prompt the **positive**." A prohibition earns its place "only as a hard guardrail you cannot phrase positively".

Earlier, in January, his refactoring prompt flagged instructions that are "Redundant (the agent already knows this)", "Too vague to be actionable" or "Overly obvious (like 'write clean code')". (*A Complete Guide To AGENTS.md*) **[V]**

## 4. What to keep

- **January 2026: an explicit minimum.** "Be ruthless about what goes here. Consider this the absolute minimum: One-sentence project description (acts like a role-based prompt) / Package manager (if not npm; or use corepack for warnings) / Build/typecheck commands (if non-standard). That's honestly it." (*A Complete Guide To AGENTS.md*) **[V]**
- **February 2026: almost nothing.** The six-word WSL line, by the undiscoverable-and-global test (§1). **[V]**
- **May 2026 dictionary.** "Suitable content is whatever the agent can't derive from the code: build and test commands, conventions the codebase doesn't make obvious, hard constraints ('never edit the generated client'). Short and declarative: it's a brief, not documentation." It also offers a way in: "When you've corrected the agent for the same thing twice, that correction is a candidate line for AGENTS.md." (*AGENTS.md* entry) **[V]**
- **July 2026: what can't be found by looking.** "Cache what the agent cannot find by looking: the unwritten convention, the reason behind a choice, the gotcha no config confesses." (`writing-for-agents`) **[V]**
- **Personal, per-setup preferences.** His issue bar sends one-person tweaks to the user's own instruction file: "a config option, a harness-specific branch, or a tweak to suit one person's workflow. Those belong in your own `CLAUDE.md` / `AGENTS.md`, or in a fork." https://github.com/mattpocock/skills/blob/main/SCOPE.md **[V]** Triage replies send concrete lines there, e.g. "add 'When grilling, ask one question at a time.' to your global CLAUDE.md" (https://github.com/mattpocock/skills/issues/1297) and "A line in your own CLAUDE.md ('CLAUDE.md is a symlink: edit it in place') covers it" (https://github.com/mattpocock/skills/issues/1275). **[C]** His own published global rules include two plan-mode lines ("Make the plan extremely concise. Sacrifice grammar for the sake of concision." and a list of unresolved questions at the end). *My AGENTS.md file for building plans you actually read*, 2026-01-13. https://www.aihero.dev/my-agents-md-file-for-building-plans-you-actually-read **[V]**
- **Domain terms over file paths.** "Instead of documenting structure, describe capabilities. … Domain concepts (like 'organization' vs 'group' vs 'workspace') are more stable than file paths, so they're safer to document. But even these can drift … Keep a light touch." (*A Complete Guide To AGENTS.md*) **[V]** His later setup skill moves the domain vocabulary out to `GLOSSARY.md` and leaves a one-line pointer (§5). **[V]**

## 5. Where everything else goes

He names five destinations. Which one depends on what the line is:

| Kind of line | Destination | Source |
| --- | --- | --- |
| Detail needed in one area (TypeScript rules, testing, API design) | A separate doc behind a one-line pointer, nested if needed | *A Complete Guide To AGENTS.md* **[V]** |
| Steering preferences (reducers for UI state, a testing pattern) | A skill: "discoverable instructions that the agent can pull in when relevant" | *Never Run Claude /init* **[V]** |
| A rule about which CLI to run, or a banned command | A deterministic hook (`PreToolUse`, exit 2) | *How to use Claude Code hooks…*, 2026-02-25 **[V]** |
| A mechanical coding rule (banned API, import shape, file location) | A lint rule, pre-commit hook or CI job | `retro` SKILL.md **[V]** |
| A judgement-call coding standard | `CODING_STANDARDS.md`, read by the reviewer, not the implementer | `retro` SKILL.md **[V]** |
| Facts about the code itself | Nowhere: "Trust the explore step" | *Never Run Claude /init* **[V]** |

Details:

- **Progressive disclosure via pointers.** "For TypeScript conventions, see docs/TYPESCRIPT.md. Notice the light touch, no 'always,' no all-caps forcing. Just a conversational reference." Pointers can nest ("Your docs/TYPESCRIPT.md can reference docs/TESTING.md"). (*A Complete Guide To AGENTS.md*) **[V]** "Keep the always-loaded layer small: a sentence per topic and a pointer to where the detail lives." (dictionary, *Progressive disclosure*) **[V]**
- **Hooks over instructions.** "Adding 'don't use `git push`' to your CLAUDE.md reduces the chance of a force push. It doesn't prevent it. You're burning instruction budget on something that still isn't guaranteed." The article includes a prompt that converts `CLAUDE.md` instructions into hooks: "Not all the instructions will be deterministic: only do the ones you can". https://www.aihero.dev/how-to-use-claude-code-hooks-to-enforce-the-right-cli **[V]** Video: "How to actually force Claude Code to use the right CLI (don't use CLAUDE.md)", 2026-02-25. https://www.youtube.com/watch?v=3CSi8QAoN-s **[V]** (description only)
- **Standards go to the reviewer.** "The implementation agent has the most **context pressure**. … This means that the review agent should be responsible for imposing coding standards, not the implementation agent." Check category: "**Global AGENTS.md**: are there any steering instructions that should be moved to coding standards (or automated checks) instead? _Use when_ the AGENTS.md file is particularly large, in the repo OR the user's global scope." (`retro` SKILL.md, 2026-08-24, mechanical-to-check rule added 2026-09-15) **[V]**
- **Repeat mistakes: a check, not a line.** "**The agent keeps making the same mistake. Should I add a line to `CLAUDE.md`?** Usually not … If the mistake is mechanical, the fix is a check that fails. If it is a judgement call, it goes in the coding standards the reviewer reads." Its success signal: "your `AGENTS.md` gets shorter over time, not longer." (`retro` docs page) **[C]**
- **Skills: an overloaded file split into skills.** The v1.2 changelog says to use `writing-for-agents` "to pull an overloaded AGENTS.md apart into skills, which stops the front-loading." 2026-08-05. https://www.aihero.dev/skills/skills-changelog-v12-wait-what-writing-for-agents-claude-code-plugin-and-more **[V]**
- **Monorepos: nested files, each level focused.** Root: purpose, navigation, shared tools. Package: purpose, stack, conventions. "Don't overload any level. The agent sees all merged AGENTS.md files in its context." (*A Complete Guide To AGENTS.md*) **[V]**
- **His own setup skill writes pointers.** `setup-matt-pocock-skills` adds an `## Agent skills` block where each entry is "[one-line summary …]. See `docs/agents/<file>.md`." https://github.com/mattpocock/skills/blob/main/skills/engineering/setup-matt-pocock-skills/SKILL.md **[V]**

## 6. How to word the lines that stay

- **A pointer needs a trigger as well as a path.** "A bare path is a pointer the agent has no reason to follow … Write the line so it matches how tasks present: 'release, deploy, or rollback: read `internal/deploy.md` first'." Dictionary, *Context pointer* (first committed 2026-05-05). https://github.com/mattpocock/dictionary-of-ai-coding/blob/main/dictionary/Context%20pointer.md **[V]**
- **Wording beats placement.** "The pointer's _wording_, not its target, decides when the agent reaches the material, and how reliably. A must-have target behind a weakly worded pointer is a variance bug: sharpen the wording first, and inline the material only if sharpening fails." And because an always-loaded pointer "costs on every turn", it "earns even harder pruning than the body": "Front-load the leading word", "One trigger per branch" (collapse synonyms), "Cut identity the body already carries." (`writing-for-agents`) **[V]**
- **Inline what every branch needs. Disclose what only some reach.** "Branching is the cleanest disclosure test." (`writing-for-agents`) **[V]** Which is his globality test again: "keep AGENTS.md for the lines that apply everywhere" (dictionary, *AGENTS.md*). **[V]**
- **Leading words** compress restated triads into one pretrained word (_tight_, _red_). (`writing-for-agents`) **[V]**

## 7. How to decide, and how to know you're done

- **The deletion test, run, not argued.** "Agents told to 'streamline' optimise for length, because length is the thing they can see. The no-op test checks behaviour, not style: delete the line and ask whether the agent's behaviour changed." (`writing-for-agents` docs page) **[C]**
- **Done means nothing left to cut.** "When it works, and you can no longer find duplication, sediment or no-ops. There is no automated eval. You check by running the document by hand". "It's working if: The document gets shorter as it gets better, and you are surprised how little is left." Same page. **[C]**
- **Don't let the agent write it unreviewed.** "Left alone the model explains what it already knows, and it will not apply the no-op test or reach for a leading word on its own. Use the reference to review the draft." Same page. **[C]**
- **No line or rule quotas.** Asked to add "a directive budget" (under ~25 rules, under 300 lines): "A hard line or rule budget is also more prescriptive than I want the skill to be." 2026-10-07. https://github.com/mattpocock/skills/issues/1113 **[C]**
- **Change on evidence.** For his own skills, "I only change skills in response to a failure in a real run" (same reply, and the "Observed failure" bar in `SCOPE.md` **[V]**). `retro` likewise proposes environment changes only from the session's own record. (`retro` docs page) **[C]** He doesn't state this rule for `CLAUDE.md` lines directly. It's the same discipline applied to his skills. **[U]**
- **Use `retro` as the recurring pruning pass.** Its categories include "**No-ops**: look for instructions in steering files that don't modify the agent's behavior. _Use when_ the steering files are large and unwieldy." (`retro` SKILL.md) **[V]** Its docs page admits a limit: it judges deletions "against the one session it reads, so treat each one as a candidate for the deletion test, not a verdict." **[C]**
- **New models: another no-op pass.** "Updating for a new model is usually another no-op pass rather than a rewrite." (`writing-for-agents` docs page) **[C]**
- **Memory files need the same pruning.** "A memory system needs pruning, the same way AGENTS.md does." (dictionary, *Memory system*) **[V]** Later he goes further: video "Kill your MEMORY.md", 2026-07-17: "why you should disable auto-memory in Claude Code and keep your AI agent completely stateless for predictability." https://www.youtube.com/watch?v=A0scuiiGBC4 **[V]** (description only)
- **Measure the payload.** For the harness side, his guide runs `/context` before and after trimming. It reports "memory files" as a category, among others. *How to kill the bloat in Claude Code's system prompt*, 2026-07-07. https://www.aihero.dev/how-to-kill-the-bloat-in-claude-codes-system-prompt **[V]**

## What this means for our instruction files

All inference from the sources above. **[U]**

- **The shared root `CLAUDE.md`** (earlyoom, vitest worker cap) passes his bar. Like his WSL line, it's an environment fact the agent can't discover, and it applies to every session. Its triage steps for a killed command apply only after a kill. By his branching test, that recovery procedure could sit behind a pointer ("If a command dies with 137/143 or `Killed`, read …"). Keep the always-on rule (`--maxWorkers=4`) inline.
- **The project `CLAUDE.md`** mostly follows his pattern already: one-line project description, then one-line pointers with front-loaded triggers ("Before touching picks, queues, …, read `docs/agents/pick-effects.md`"). That's the shape of his `setup-matt-pocock-skills` block and his context-pointer advice.
- **"Running tests"** is a cache with a reason: `ng test` rejecting `--maxWorkers` is "the gotcha no config confesses", so it stays. Under his hooks advice, the "don't pass `--maxWorkers` to the web workspace" rule could also be a `PreToolUse` hook instead of a prose line.
- **"File layout"**: the TypeScript 1000-line limit is enforced by lint, so restating it is a cache (the lint error explains itself). The part lint doesn't enforce (templates, styles, JSON fixtures) is the line worth keeping. Under `retro`'s split, it's a judgement-call standard the reviewer could own instead of the implementer.
- **Pruning method**, his way: run the no-op test sentence by sentence and delete whole sentences. Settle doubtful lines by running a session without them. Move mechanical rules to checks. Don't set a line quota.
